# Qwen3.8 + DFlash2：4K 输出配对测试

日期：2026-10-07。状态：已完成诊断与统计修复，正式三轮待完成，尚无配对性能结论。

## 目的与范围

按用户要求将正式输出长度设为每请求 4096 tokens。此前约 128 输入、
64 输出的短请求结果不能代表长输出投机收益。本轮保持模型和验证实现不变，
单独测量长输出条件下的端到端吞吐、解码阶段耗时、延迟、接受率及显存。
用户随后明确选择自然需要长输出的代码／推理任务，替换原来的短提示。

## 配置

- 单张 A800-SXM4-80GB，C4、K=7、验证块长 4、micro-batch 4。
- 每轮 4 个完整代码／推理任务，输入长度依次 187、194、190、201 tokens；各输出 4096。
- 使用模型聊天模板，模板默认包含 xhigh reasoning 设置。输出计数包括推理 token。
  完整任务和模板原样保留，不按固定输入长度截断。
- 三轮配对，同样的输入与 seed；顺序为 target/DFlash、DFlash/target、target/DFlash。
- greedy、ignore_eos=True；每轮每模式共 16,384 输出 tokens。
- 两模式均启用共同 vectorized target 数值路径与融合 GDN。
- 两模式均开启 `--lightweight-live-stats`：运行中只读取当前计数，计时结束后
  通过工作线程命令导出完整历史。接受历史不截断，逐 token 输出日志完整保留。
- 在线预热为 4 个请求、各 64 输出 tokens；正式请求仍为 4096。
  引擎另有最大模型窗口的初始化预热。加载和两类预热均排除在正式计时之外。
- 长窗口会改变固定 attention padding；严格比较针对本轮两模式，
  不要求与 64 输出配置的历史序列前缀相同。
- 固定长度合成负载用于性能与实现一致性检查，不代替自然 EOS 或质量评测。

### 原短提示的 4K 诊断

`c4_decode4096_r0_20261007` 完成 target-only 四请求、16,384 输出 token：
26.4037 tok/s，总耗时 620.519 秒，其中 prefill 37.823 秒、target decode
393.988 秒，剩余 188.708 秒在模型调用之外，包含统计、输出投递及调度等。
发现实时快照每步对全部历史记录调用 dataclasses.asdict，总工作量随步数
呈二次增长；4095 条历史的独立 CPU 快照中位耗时约 56.23 ms，1024 条
约 14.07 ms。轻量计数快照低于 0.001 ms，不序列化历史。不能把剩余的
188.708 秒全部归因于统计，但已确认这是显著的测量干扰。

此轮四请求首次 EOS 位置分别为 1104、313、无、985；后两条有大量低多样性
续写。该短提示强制 4K 负载不适合充当自然长回答的主要性能证据。已保存
target 完整结果，在 DFlash2 初始化期间终止该实验进程组，没有形成有效配对。
所有旧文件保留；用户明确同意改用自然长任务。
